# 农产品电商系统活动图文字描述

## 1. 用户注册与认证流程

**流程描述：**

1. **初始节点** → 用户访问系统
2. **活动：填写注册信息** → 用户输入用户名、密码、手机、邮箱等信息
3. **决策节点：选择角色类型** 
   - [普通用户] → 活动：创建普通用户账户
   - [农户] → 活动：创建农户账户（待认证状态）
4. **活动：MD5加密密码** → 系统对密码进行加密处理
5. **活动：保存用户信息到数据库**
6. **决策节点：是否为农户角色？**
   - [是] → 活动：等待管理员认证 → 活动：管理员审核农户资质 → 决策节点：审核结果
     - [通过] → 活动：更新认证状态为已认证
     - [拒绝] → 活动：通知用户审核未通过
   - [否] → 合并节点
7. **合并节点** → 活动：注册成功，跳转登录页面
8. **活动最终节点**

## 2. 商品发布与管理流程

5. **活动：设置上架状态** → 选择是否立即上架
6. **活动：验证商品信息完整性**
7. **决策节点：信息是否完整？**
   - [否] → 活动：提示错误信息 → 返回活动：填写商品信息
   - [是] → 活动：保存商品到数据库
8. **活动：关联农户ID** → 建立商品与农户的多对一关系
9. **活动：返回商品列表**
10. **活动最终节点**

## 3. 订单创建与支付流程

**流程描述：**

1. **初始节点** → 用户浏览商品
2. **活动：选择商品** → 用户点击商品查看详情
3. **活动：选择购买数量**
4. **活动：验证库存充足性**
5. **决策节点：库存是否充足？**
   - [否] → 活动：提示库存不足 → 流最终节点
   - [是] → 活动：添加到购物车
6. **决策节点：是否继续购物？**
   - [是] → 返回活动：选择商品
   - [否] → 活动：进入结算页面
7. **活动：填写收货信息** → 输入收货人、电话、地址
8. **活动：选择支付方式**
9. **决策节点：支付方式类型**
   - [在线支付] → 分叉节点（并发开始）
     - 并发线程1：活动：生成订单号
     - 并发线程2：活动：计算订单总金额
     - 汇合节点 → 活动：创建订单记录（状态：待支付）
     - 活动：调用支付接口
     - 决策节点：支付是否成功？
       - [成功] → 活动：更新订单状态为已支付 → 活动：扣减商品库存
       - [失败] → 活动：提示支付失败 → 流最终节点
   - [货到付款] → 活动：生成订单号 → 活动：计算订单总金额 → 活动：创建订单记录（状态：待发货）
10. **合并节点** → 活动：保存订单明细（订单ID、商品ID、数量、单价、小计）
11. **活动：返回订单详情页面**
12. **活动最终节点**

## 4. 订单状态流转流程（含泳道）

**泳道划分：**
- 泳道1：普通用户
- 泳道2：系统
- 泳道3：农户
- 泳道4：物流

**流程描述：**

1. **初始节点**（泳道2：系统）
2. **活动：订单创建成功**（泳道2：系统）→ 订单状态：待支付
3. **决策节点：用户操作**（泳道1：普通用户）
   - [取消订单] → 活动：更新订单状态为已取消（泳道2：系统）→ 活动：恢复商品库存（泳道2：系统）→ 活动最终节点
   - [修改收货信息] → 决策节点：订单是否已支付？（泳道2：系统）
     - [否] → 活动：更新收货人、电话、地址（泳道2：系统）→ 返回决策节点：用户操作
     - [是] → 活动：提示无法修改（泳道2：系统）→ 返回决策节点：用户操作
   - [完成支付] → 活动：更新订单状态为已支付（泳道2：系统）
4. **活动：通知农户发货**（泳道2：系统）
5. **活动：农户确认订单**（泳道3：农户）
6. **活动：打包商品**（泳道3：农户）
7. **活动：更新订单状态为已发货**（泳道2：系统）
8. **活动：物流配送**（泳道4：物流）
9. **活动：用户签收**（泳道1：普通用户）
10. **决策节点：用户操作**（泳道1：普通用户）
    - [确认收货] → 活动：更新订单状态为已完成（泳道2：系统）
    - [申请退货] → 活动：联系客服处理（泳道2：系统）→ 流最终节点
11. **活动：订单完成**（泳道2：系统）
12. **活动最终节点**

3. **决策节点：选择操作类型**

## 活动图绘制要点

### 核心元素使用规范：
1. **初始节点**：每个流程图顶部使用实心圆点 ●
2. **活动节点**：使用圆角矩形，命名采用"动词+名词"格式
3. **决策节点**：使用菱形 ◇，每个输出流附带监护条件（用方括号标注）
4. **合并节点**：使用菱形 ◇，表示"逻辑或"（任意一个到达即继续）
5. **分叉/汇合节点**：使用粗横线 —，表示并发控制（分叉拆分线程，汇合同步线程）
6. **活动最终节点**：使用圆圈内含实心圆点 ◉，终止整个流程
7. **流最终节点**：使用圆圈内含叉号 ⊗，仅终止单个分支

### 对象流（可选增强）：
- **对象节点**：矩形表示数据对象（如"订单对象"、"商品对象"）
- **对象流**：虚线箭头连接活动与对象节点

### 泳道使用场景：
- 订单状态流转流程需要使用泳道区分不同参与者（用户、系统、农户、物流）
- 垂直泳道从左到右排列，每个泳道代表一个角色的职责范围

### 并发控制示例：
- 订单创建流程中，"生成订单号"和"计算订单总金额"可以并发执行，使用分叉节点拆分，汇合节点同步后再创建订单记录
- 商品搜索流程中，"加载分类列表"、"加载热门商品"、"加载推荐商品"可以并发执行

### 循环结构表示：
- 搜索防抖流程中，"重置计时器"通过控制流箭头返回到"计时器是否到期？"决策节点，形成循环等待
- 用户继续购物流程中，通过"是否继续购物？"决策节点的[是]分支返回到"选择商品"活动，形成循环

## 绘图工具建议

推荐使用以下工具绘制活动图：
1. **PlantUML**：支持文本描述生成UML图，适合版本控制
2. **draw.io**：免费在线工具，拖拽式操作
3. **Visual Paradigm**：专业UML建模工具
4. **StarUML**：开源UML工具

绘图时注意：
- 保持流程从上到下或从左到右的清晰走向
- 避免控制流交叉，必要时使用桥接符号
- 决策节点的所有输出路径必须有明确的监护条件
- 并发线程的分叉和汇合必须成对出现
